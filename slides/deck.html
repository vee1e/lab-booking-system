Shared Laboratory Equipment / problemIA3

Sharing instruments without a register.

01 / CLAIMTwo students can book the same microscope for the same afternoon.

02 / TRACEOnce an instrument leaves the shelf, nobody can say who has it.

03 / COSTLate returns are remembered, not recorded, so no fine can be charged.

One console app that holds the register.

A C++17 build with no database. Gear, users and bookings live in memory, and every rule sits in one class. Borrowing an item marks it taken, returning it closes the record and prices the delay.

Two hierarchies carry the data. One manager class enforces the rules.

Hierarchy03
Class relationships / who owns whatBooking.h · BookingSystem.h

Composition holds the lists. Association links a record.

borrow() checks user, gear and quota, then writes a Booking and calls markBorrowed(). One door for every rule.
Composition
BookingSystem owns the three lists and frees every pointer in its destructor. Kill the manager and the register dies with it.
Association
A Booking stores a user id and a gear id. It does not own either object, so a deleted item cannot leave a broken pointer behind.
Dependency
main talks only to BookingSystem. It never reaches into the vectors, so every rule passes through one door.

Build and limits / what existsmain.cpp

One command, no dependencies.

# build
g++ -std=c++17 -Wall main.cpp -o labbook

# run
./labbook

Five headers and one main file. Standard library only, and the build is warning free.

In memory only
Gear, users and bookings reset when the process ends. No database was allowed, so none is used.
Manual day counter
Day moves with one menu key. Dates are relative, not calendar dates.
